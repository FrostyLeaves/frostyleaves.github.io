Nsight Graphics 2026.4 新增了 MCP Server，AI agent 可以直接调用 Nsight 的采集和查询接口，读取 GPU Trace、Graphics Capture 和 Aftermath 崩溃 dump。

本次试用的是 Nsight Graphics 2026.4.0，测试环境是 RTX 4070 Ti 和 Vulkan。测试对象包括几个瓶颈已知的小程序、已有项目的 capture，以及 Unity 的 GPU Trace。最明显的区别是两种接口模式提供的数据范围：Workflow 适合快速浏览，Native 才能覆盖按 pass 查询、源码热点和图形状态检查这些日常操作。

Workflow 与 Native

默认的 Workflow 将帧、marker、指标、draw 和资源等整理成统一的表，agent 用类似 SQL 的方式查询。Native 暴露更多细粒度操作，可以选择 GPU Trace 中的 marker 或时间范围，也能检查 Graphics Capture 中的具体 draw 和资源。

官方将 MCP Server 标为 Alpha，2026.4 先在 Windows 提供；Native 的接口仍具有实验性质。2026.4 更新说明

下面按这次试用记录列出两种模式的能力。标为“未实测”的项目仅确认了接口能力，尚未验证实际效果。

采集和 GPU Trace 查询

Native 可以指定采集开始的帧或时间、采集帧数和指标集。本次让它启动测试程序，等待第 120 帧，再采集 5 帧并写出文件，整个操作约需 5～7 秒。这段时间包含程序运行和等待，反映的是这次采集任务的总耗时。

拿到 trace 后，可以读取各 pass 的 GPU 时间，并按 marker 实例或时间范围查询吞吐、占用率和缓存命中等指标。Shader Profiler 也可以限定到某个 pass，返回热点 shader、stall 原因和关联源码行。本次测试已通过接口定位到测试 shader 中的具体分支位置，无需再手动进入 GUI 查找。

已有 trace 同样可以打开，包括通过 GUI 采集、由其他人提供的文件。Workflow 也支持读取这类 trace 和各 pass 的耗时，但本次无法把硬件指标按 pass 拆开，shader 查询范围也限于整段 trace。

Graphics Capture 检查

Native 能读取 draw 参数，以及 blend、深度附件格式、viewport、绑定 shader 等 pipeline 状态。纹理和 buffer 既可以查看格式与大小，也可以读取内容。

本次用一个已知设置的 draw 检查返回结果，得到的 16 个实例、D32 深度附件和 2560 × 1440 viewport 均与程序配置一致。Workflow 在相同类型的检查中存在实例数漏计和资源字段为空的问题，因此我暂时不会依赖它完成 capture 的详细检查。

Native 还可以重放 capture，取得每个 draw 的 GPU 耗时。工具提供了替换 shader 后重放的能力，但这部分本次没有实测，暂时不能评价其兼容性或修改效果的验证流程。

Aftermath GPU 崩溃 dump 也在两种模式的能力范围内。本文的具体试用主要集中在 GPU Trace 和 Graphics Capture，没有展开崩溃 dump 的案例。

当前的功能缺口

逐 draw 的硬件计数器还没有开放。 本次 Native 工具目录中没有找到 Range Profiler 接口。GPU Trace 提供的是时间范围内的采样指标，replay 提供逐 draw 耗时，两者不能替代单个 draw 的吞吐、缓存命中率等计数器。

Pixel History 和 Shader Debugger 也未出现在本次工具目录中。 像素历史与 shader 单步调试尚不能通过这些 MCP 接口完成，需要回到 GUI 或其他工具。Shader Profiler 的源码热点查询与 Shader Debugger 是两项不同的能力。

批量查询和聚合仍需外层处理。 本次指标接口按一个指标、一个时间范围查询，10 个 pass 的 7 项指标需要组织 70 次调用。跨帧平均和多次采集的 A/B 对比也需要自行汇总；这些操作还没有形成方便的批量接口。

没有自动诊断和异常样本筛选。 MCP 返回指标与状态，本次没有提供瓶颈判定、外部 GPU 负载提示或受干扰帧剔除功能。这些能力仍要由使用它的 agent 或分析工具补充。

Workflow 还需要补齐采集范围控制、draw 与 shader 的对应关系和资源信息，并修正本次遇到的实例数问题。相较之下，Native 已能承担更多实际查询工作，但接口升级后的兼容性仍需留意。

接入方式

Windows 安装包中的 ngfx-mcp.exe 位于 host/windows-desktop-nomad-x64。默认启动后，兼容客户端通过 Streamable HTTP 连接 http://127.0.0.1:7661/mcp。

Native 使用渐进式工具发现，两种模式的工具名称和会话行为不同，需要按所选模式配置客户端。官方目前要求 agent 与服务端运行在同一台 Windows 机器上。MCP 接入说明

本次尚未验证 Claude Code 的直接接入，也没有完成远程测试机、D3D12 和真实游戏 live 采集测试。

总结

Workflow 支持的功能有限，反而 Native 更适合接入到性能分析自动化流程里。Native 能完成采集控制、pass 指标查询、源码级 shader 热点查询、pipeline 和资源检查，以及外部 trace 的读取。Workflow 受采集限制和 capture 数据缺失影响，更适合快速浏览，暂时不适合承担日常的详细检查。

对已有的 nsight-graphics-analyzer，Native 最值得补进来的能力是源码级热点、较完整的图形状态与资源检查，以及读取外部 trace。原有的判定和统计逻辑可以继续保留。后续更期待批量指标查询、逐 draw 计数器和调试接口，让这些能力也能直接接入自动化工具。

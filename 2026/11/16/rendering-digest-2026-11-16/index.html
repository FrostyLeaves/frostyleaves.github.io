Nanite Dynamic Wind 植被风模拟

植被风动画常用材质里的 World Position Offset（WPO）偏移顶点。用在 Nanite 植被上时，除了逐顶点计算，还要处理运动后的剔除边界：材质可以任意移动顶点，开发者只能按最大位移预留空间。包围盒扩大后，一些原本可以剔除的几何也会留下来。

UE 5.9 的 Dynamic Wind 在 GPU 上模拟植物骨骼，再由 Nanite Skinning 驱动网格。它根据植物几何估算受力参数，共享普通风动的模拟结果，并为受到局部作用的植物分配独立模拟。本文依据 UE 5.9 文档整理；插件目前仍为 Experimental。

骨骼动画怎样配合 Nanite

Nanite Skinning 可以根据蒙皮矩阵计算变形后的包围盒，减少 WPO 所需的保守扩张。材质之间不同的 WPO 逻辑还会拆出更多 programmable raster bins，增加 GPU 调度工作；改用骨骼驱动风动画后，这条路径可以使用固定功能光栅化。Nanite Foliage 文档

这部分由 Nanite Skinning 处理。Dynamic Wind 则负责计算骨骼怎样运动，下面从它需要的输入开始。

植物几何提供哪些参数

Dynamic Wind 在编辑阶段分析源几何和蒙皮权重，保存每根骨骼的质量、迎风面积、质心和压力中心。质量描述骨骼所承担的负载，迎风面积描述它接收风力的面积；质心和压力中心分别记录质量与风压的等效作用位置。

这些数据包含骨骼所连接的子枝叶。例如，树冠的质量和受风面积会计入树干的负载。木材和叶片使用各自的密度参数：木材按体积换算质量，叶片按面积换算质量。这样，换一株形状不同的植物时，受力参数也会随几何重新计算，减少手工校准。Dynamic Wind 文档

风力怎样驱动骨骼

运行时，系统每帧计算全局风和局部作用对骨骼产生的弯曲力，再更新两种运动：

  • **Sway（摇摆）**由阻力驱动，表现树干和大枝较慢的倾斜与回摆。
  • **Flutter（颤动）**由风经过枝条产生的涡旋驱动，表现较快的细小运动；风增强时，颤动的频率和强度也随之变化。

两种运动合成为每根骨骼的旋转。官方说明，同一根枝条使用 3 根或 10 根骨骼，总弯曲量保持一致，因此可以增加骨骼细分来描述形状，而不额外增加整根枝条的弯曲量。

Epic 在 2026 年 9 月的开发答复中进一步说明了弹簧模型：Sway 使用欠阻尼振子，Flutter 使用临界阻尼振子，两者都带有惯性和阻尼。欠阻尼响应允许受力后继续回摆，临界阻尼响应则较快地收敛。这里描述的是当时面向 5.9 开发的实现。Epic 开发者答复

每根骨骼独立进行弹簧模拟，系统没有完整的骨骼间约束求解器。前面的负载汇总提供了各骨骼的受力参数，骨骼之间的约束和接触仍不能按完整的树木动力学求解。

共享风动与局部交互

只受全局风影响的植物复用按风向组织的少量模拟结果，不必逐株更新独立状态。受到局部作用后，相应实例才转入独立模拟。

局部作用有三种输入：

  • Dynamic Wind Force 提供局部空气作用，可配置方向风、径向风、旋涡等形状。
  • Push Capsule 将骨骼推出胶囊范围，用来表现角色或物体与植被的接触。
  • 外部速度体积 提供空间变化的空气速度，可接入风场数据。

转入独立模拟时，实例从当前共享运动接续，避免姿态跳变。局部作用消失后，它仍会继续模拟一段时间，再混合回共享运动。这个恢复阶段默认持续 3 秒，由 DynamicWind.DemoteGracePeriod 控制。延长它可以保留更长的独立运动，但也会延长实例占用模拟预算的时间。

预算按网格限制，项目默认最多允许 256 个实例同时独立模拟，可通过 Max Active Instances 覆盖。超出预算的植物继续播放共享风动，无法得到本次局部作用对应的独立响应。交互覆盖范围较大时，需要同时检查实例上限和恢复时间。Dynamic Wind 文档

共享机制减少的是重复的风模拟求解。每株植物的变形、光栅化与阴影仍有成本；Nanite Foliage 文档建议通过 Animation Min Screen Size 在远处停用动画，以控制 Virtual Shadow Map 开销。Nanite Skinning 性能建议

与 WPO 的取舍

对已经使用 Nanite 骨骼植被、需要局部风场或角色交互的项目，我倾向于优先评估 Dynamic Wind。它已有几何分析、接触输入和独立模拟的分配机制，新增交互可以沿这套骨骼系统实现；Nanite Skinning 也能改善 WPO 的剔除边界和光栅调度问题。

已有静态植被资产则要补充骨骼、蒙皮和模拟组数据。运行时还需要为局部交互安排实例预算，并接受独立弹簧模型的近似。仅需轻微周期摆动、已有成熟 WPO 资产的项目，迁移的收益未必足以抵消资产改造工作。我会先用代表性植被验证画面，再在相同场景中比较 GPU 时间。

接入条件

Dynamic Wind 需要 Shader Model 6。PVE 输出的 Nanite Assemblies 网格还需要启用 Nanite Foliage 才能正确构建。对于非 Nanite 骨骼网格，官方要求在 LOD 构建设置中启用 Optimize For Instancing，否则 Dynamic Wind 会跳过该网格。

模拟组数据通过 PVE、USD 或 JSON 导入，目前不能在编辑器中手工创建。实例组件必须使用 Dynamic Wind Data 作为 Transform Provider，才能注册到风系统。几何分析需要源几何和蒙皮权重，未完成或失败时植物会停在绑定姿态。

低端硬件可将 DynamicWind.Mode 设为 0，使用无逐植物状态的参数化动画；这个模式不支持局部力和推挤胶囊。

以上条件以 UE 5.9 Dynamic Wind 专页为准。Nanite Foliage 总览页仍保留“只支持全局风、没有玩家碰撞”的旧限制，与专页不一致，本文按专页介绍交互功能。Epic 仍提醒谨慎将 Experimental 功能用于正式发布项目。

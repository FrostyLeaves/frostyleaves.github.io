DXR 的 CLAS 与 PTLAS

动态场景的光追开销包含两部分：更新加速结构，以及用它追踪光线。模型变形、LOD 切换和实例移动都会影响前一部分。传统 DXR 以 BLAS 管理几何，以 TLAS 管理实例，局部变化也可能带来较大范围的结构更新。

微软在 2026 年 10 月 28 日发布的 DXR 预览增加了 Clustered Geometry 和 Partitioned TLAS。前者把几何构建拆成可复用的小簇，后者让场景更新集中在发生变化的分区。两者可以独立使用。

CLAS 复用几何簇

传统 BLAS 从三角形集合构建。Clustered Geometry 先把空间邻近的三角形组成簇，为每簇建立 CLAS，再由 CLAS 的引用构建 Cluster BLAS。TLAS 中的实例仍然引用 BLAS。

一个 CLAS 最多包含 256 个三角形和 256 个不同的顶点索引。多个 Cluster BLAS 可以引用同一个 CLAS。LOD 或流式加载改变簇的组合时，已有 CLAS 可以继续使用，重新组装的输入也缩小到了簇这一层。引用关系需要维护，CLAS 内容或地址改变后，依赖它的 Cluster BLAS 会失效，需要重建。DXR 规范

动画复用拓扑模板

骨骼动画每帧改变顶点位置，三角形连接关系通常保持不变。Cluster Template 提前完成与位置无关的构建工作，保存可重复使用的拓扑等信息。每帧将变形后的顶点位置填入模板，生成 CLAS，再组装 Cluster BLAS。模板本身不能用于光线求交。

Clustered Geometry 用模板实例化处理动态几何，不提供传统的 refit。相同拓扑还会出现在细分地形中，NVIDIA 的示例使用有限种细分模式生成模板，运行时为它们提供实际位置。NVIDIA 技术介绍

PTLAS 保留未变化的分区

PTLAS 把实例分配到多个分区。每个分区有自己的加速结构，上层结构再将这些分区组合起来。实例记录持续保留，更新时提交发生变化的记录，未变化的分区继续复用之前的结构。

频繁移动的实例可以放进 global partition，其中每个实例在构建和遍历时近似作为独立分区处理，减少它带动普通空间分区反复重建的成本。分区边界重叠会影响遍历效率，因此空间划分和动态实例的归属也成为应用需要管理的内容。NVIDIA 技术介绍

API 区分两种实例操作。修改变换使用 WRITE_INSTANCE，UPDATE_INSTANCE 只修改 BLAS 地址和 hit-group-table contribution。稀疏写入中的 InstanceIndex 是持久记录的编号，与本帧写入数组中的位置无关。DXR 规范

GPU 生成构建任务

新的 ExecuteIndirectRTASOperations 从 GPU 内存读取批量参数，compute shader 可以直接生成工作。CLAS 构建、Cluster BLAS 组装和 PTLAS 更新由此能接入 GPU 驱动的几何流程。

同一次调用里的操作不能相互依赖。先构建 CLAS，再组装 Cluster BLAS，最后更新 PTLAS，需要拆成不同调用，并在依赖阶段之间插入 barrier。微软 API 介绍

接入价值与代价

相对每次从三角形重建 BLAS，CLAS 的价值在于复用已构建的簇和模板。PTLAS 则适合大量实例中只有局部发生变化的场景。已有 meshlet、LOD 和场景分区的引擎，可以沿用这些组织方式来划分簇与分区。

新增的管理成本也很具体：簇引用的生命周期、分区归属、构建缓冲区和阶段同步都需要接入引擎。构建节省与遍历成本应分开观察。微软展示的样例中，scratch 显存可能显著增加，PTLAS 的遍历时间也可能上升。实际收益要看两部分成本相加后的结果。

微软的 Clustered Geometry 样例支持切换传统重建、refit 和簇路径，分别记录 AS 构建、追踪与显存。它刻意给复制物体建立独立 BLAS，并非优化过的实例化基准。相同变形的实例在实际引擎里可以共享传统 BLAS，因此不宜直接套用该压力场景的收益倍率。

阅读代码可以从 BuildClasImplicit 和 BuildBlasFromClasIndirect 开始，再看 BuildAnimatedObjectSetup、UpdateAnimatedObjectPerFrame 与对应的 GPU 参数写入 shader。本文核对的是 Agility SDK 1.722.0-preview 及 2026 年 11 月 11 日的 DXR 规范 v0.39，仍处于预览阶段，运行需要匹配的 SDK、编译器与支持驱动。

RenderDoc Graph Viewer 插件介绍

RenderDoc Graph Viewer 是我做的一个 RenderDoc 插件，用于快速预览一帧渲染管线的结构，查看各个 Pass 的输入输出及其依赖关系。

它把 capture 里的 Pass、纹理和 Buffer 连成一张关系图，方便追踪资源由谁写入、被谁读取，也能帮助定位可能多余的输入和未被后续 Pass 使用的输出。这些关系可以作为排查线索，是否需要保留仍要结合资源的实际用途判断。

插件支持按 Debug Marker 展开子图、追踪同一资源的多次写入、归并重复节点，也可以从图中跳转到 RenderDoc 的事件和资源查看器。

Pass 与资源关系

图中的 Pass 和资源交替排列。红色连线表示 Pass 写入资源，绿色连线表示 Pass 读取资源。Graphics、Compute、拷贝和 Present 等操作按类别显示，资源则区分颜色附件、深度附件、Buffer 和 Swapchain 等类型。

沿着连线可以追踪一份中间结果的去向。例如 GBuffer 写出的纹理被 Lighting 读取，Lighting 再把 Scene Color 交给后处理。纹理节点上的眼睛按钮可以请求缩略图，便于在关系图里确认中间结果。

这张图根据 capture 中的事件、资源使用记录和管线状态生成。它提供 frame-graph 风格的预览，不要求引擎本身使用某一种 Render Graph 框架。

同一资源的多次写入

一张 Render Target 在一帧中可能被多个 Pass 先后修改。只画一个资源节点，会把不同时间的读写连到一起，难以区分一次读取对应哪次写入。

Graph Viewer 按写入阶段拆分资源节点，并用版本编号区分。读取连线连接到它所消费的写入版本。选中一个版本时，同一资源的其他版本也会描边，方便沿着图查看它的变化。

图中 GBuffer 先写入 Albedo 的第一个版本，Decals 读取并修改它，Lighting 使用第二个版本。资源拆分后，读写顺序可以从左向右展开。这里的版本属于图的展示结构，不会额外分配 GPU 纹理。

子图与传送门

整帧的所有 Pass 平铺在一起，节点和连线会很多。插件利用 RenderDoc 的 Debug Marker 层级，把一个标记区域收进 Sub-graph 节点。双击节点后，可以查看该区域内部的 Pass 和资源。

子图也需要保留与外部的联系。当前区域使用的外部输入带有斜线背景，相关的上游或下游子图则以 Portal 节点显示。双击 Portal 可以跳到对应子图，通过面包屑和返回按钮继续导航。

上图只展开 Scene Rendering。左侧 GBuffer 和 Shadows 提供输入，右侧 Post FX 消费输出。查看 Lighting 的读写关系时，外部区域不必全部展开，也能保留数据从哪里来、到哪里去的信息。

重复节点归并

连续的同类操作可以归并成一个节点，减少图中的重复内容。归并节点会列出成员，双击成员行仍能跳到对应位置。成员超过 24 项时，列表会折叠。

归并采用启发式判断，不能只看名字相似。节点需要同时满足读写连接结构和类别一致、名称结构相似、数量至少为 3、提交顺序连续，并且涉及相同的资源版本。图中的 18 次连续 CopyBufferRegion() 因而显示为一个 ×18 节点。

读写状态与未使用绑定

深度附件绑定到 Pass 上时，可能只参与深度测试，也可能同时写入。插件针对不同图形 API 解析相应的管线状态，把深度附件的访问区分为读取、写入或读写，避免把只读深度的 Pass 画成新的写入者。

Shader 资源也有类似情况。插件可以进一步分析资源访问，对能够确定的绑定细化读写方向。未能识别的情况继续保留 RenderDoc 提供的保守结果。

可选的未使用绑定检测会把已绑定、但能确认未被 Shader 使用的读边画成虚线。这个标记用于检查多余绑定，不代表每一条实线都已经证明发生了实际采样。默认资源使用记录仍可能包含绑定但未使用的资源。

与 RenderDoc 联动

图形窗口保留了继续查看事件和资源的入口：

  • 点击 Pass 会把 RenderDoc 的当前事件切到该节点的最后一个事件。
  • 双击纹理节点会打开 Texture Viewer。其他资源可进入 Resource Inspector。
  • 双击归并节点中的成员行可以定位具体事件。
  • 点击纹理节点的眼睛按钮按需生成缩略图。部分纹理格式可能无法预览。

显示选项、节点归并和资源候选范围集中在配置面板中，修改后通过 Apply 应用。配置保存在 %APPDATA%\qrenderdoc\renderdoc_graph_viewer.json，下次打开时可以沿用。

安装

插件要求官方构建的 RenderDoc 1.33 或更新版本，需要其中捆绑的 PySide2。

  1. 从项目仓库下载代码，把 renderdoc_graph_viewer 文件夹复制到 %APPDATA%\qrenderdoc\extensions。
  2. 确认目录结构为 extensions\renderdoc_graph_viewer\extension.json，避免多套一层仓库目录。
  3. 打开 RenderDoc 的 Tools → Manage Extensions，勾选 renderdoc-graph-viewer。需要自动加载时勾选 Always Load。
  4. 加载 capture，然后打开 Window → Graph Viewer。窗口会自动解析当前 capture。

项目已测试 Direct3D 11、Direct3D 12 和 Vulkan，OpenGL 尚未测试。依赖关系目前以整张纹理或整个 Buffer 为单位，不区分 mip、slice 等子资源。子图层级来自 capture 中的 Debug Marker，标记的组织方式也会影响浏览体验。

插件采用 MIT 许可，代码与使用说明均在 GitHub 仓库中。
